Bubble Probe: finding a colour chain in one frame

In a bubble shooter, the bubble you fire joins a group of the same colour. If the group has three or more, it pops, and anything left hanging falls. This tutorial shows how to find that group in Scratch, using touching blocks instead of a grid list, and how to make the whole search happen between two screen refreshes.

Download bubble-probe.sb3 Play the demo

The idea

The earlier Bubble Chain demo let the chain spread visibly: each round, bubbles touching a glowing ring put on a ring of their own. It works, but it takes one frame per ring of bubbles. Bubble Probe gets the same answer at once by combining three things:

One sprite per colourBubble1 … Bubble6. Asking touching Bubble3? means "is a blue bubble here?".
An invisible ProbeA tiny dot that jumps to a slot and asks that question. It never shows on screen.
Run without screen refreshThe Probe's custom blocks finish all their loops before Scratch draws the next frame.
1

A honeycomb board made of clones

The board has 12 rows of 8 slots. Odd rows are shifted half a bubble to the right and hold 7 bubbles. Bubbles are 26 pixels wide and rows are 22.5 pixels apart, so a slot's centre is:

  • x = -91 + col × 26 + (row mod 2) × 13
  • y = 147 − row × 22.5

The starting board is the list layout: 96 items, one per slot, holding a colour number or 0 for empty. When the list is empty the Stage fills it with a random board first.

Stage
when flag clicked
set [phase v] to [setup]
if <(length of [layout v]) = (0)> then
  random layout :: custom
end
broadcast (fill board v) and wait
broadcast (play v)
Stage · run without screen refresh
define random layout
set [i v] to (1)
repeat (96)
  set [row v] to ([floor v] of (((i) - (1)) / (8)))
  set [col v] to (((i) - (1)) mod (8))
  if <<(row) < (5)> and <not <<((row) mod (2)) = (1)> and <(col) = (7)>>>> then
    add (pick random (1) to (4)) to [layout v]
  else
    add (0) to [layout v]
  end
  change [i v] by (1)
end

Each colour sprite walks the list and makes a clone of itself on every slot of its own colour. The six sprites are identical apart from the colour number they look for; here is Bubble1:

Bubble1
when flag clicked
if <(isClone) = (1)> then
  delete this clone
else
  hide
  set [isClone v] to (0)
end
Bubble1
when I receive [fill board v]
if <(isClone) = (0)> then
  fill :: custom
end
Bubble1 · run without screen refresh
define fill
if <(isClone) = (0)> then
  set [i v] to (1)
  repeat (length of [layout v])
    if <(item (i) of [layout v]) = (1)> then
      set [row v] to ([floor v] of (((i) - (1)) / (8)))
      set [col v] to (((i) - (1)) mod (8))
      go to x: (((-91) + ((col) * (26))) + (((row) mod (2)) * (13))) y: ((147) - ((row) * (22.5)))
      create clone of (myself v)
    end
    change [i v] by (1)
  end
end

Why a custom block? All six sprites receive fill board together and share the counter i. A normal repeat loop pauses after every pass to let the other scripts run, so the six loops kept changing each other's i and no clones were made. A custom block that runs without screen refresh finishes its whole loop before any other script gets a turn.

2

A name for every slot

The search needs to remember which slots it has already visited, and each clone needs to know whether it was chosen. Both use a key: the slot's x and twice its y, rounded and joined with a comma, for example -13,294. Twice y keeps the half pixels of the 22.5 row height, so every slot gets its own key. Each clone works out its key once, when it starts, in its local variable myKey.

Bubble1
when I start as a clone
set [isClone v] to (1)
set [myKey v] to (join (round (x position)) (join [,] (round ((y position) * (2)))))
show

When a shot lands, the Shooter snaps it to the nearest slot and asks the sprite of that colour for a new clone there:

Bubble1
when I receive [add bubble v]
if <<(isClone) = (0)> and <(newColor) = (1)>> then
  go to x: (newX) y: (newY)
  create clone of (myself v)
end
3

The Probe: look at the six neighbours

The Probe is a 4 × 4 pixel dot. It is shown, but with the ghost effect at 100, so it is invisible yet still counts for touching. A hidden sprite never touches anything.

Probe
when flag clicked
set [ghost v] effect to (100)
show

The visit is one custom block. It skips slots outside the walls and above the ceiling, and slots already in seen. Otherwise it records the slot as seen, moves there and asks touching (join "Bubble" newColor)?. If the answer is yes, the slot joins the match and goes into the queue so its own neighbours are checked later.

Probe · run without screen refresh
define visit for match
set [pk v] to (join (round (px)) (join [,] (round ((py) * (2)))))
if <<<not <([abs v] of (px)) > (92)>> and <not <(py) > (148)>>> and <not <[seen v] contains (pk)?>>> then
  add (pk) to [seen v]
  go to x: (px) y: (py)
  if <touching (join [Bubble] (newColor))?> then
    add (px) to [qx v]
    add (py) to [qy v]
    add (pk) to [matchKeys v]
  end
end
4

Walk the whole chain with a queue

A queue is a to-do list of slots whose neighbours still need checking. Scratch has no list of pairs, so the queue is two lists side by side: qx and qy. The search:

  1. Starts with the bubble that just landed: its key goes into seen and matchKeys, its position into the queue.
  2. Takes the first slot out of the queue.
  3. Visits its six neighbours. Matching ones join the queue.
  4. Repeats until the queue is empty.

Programmers call this a breadth-first search, or a flood fill. At the end, matchKeys lists every bubble in the group.

Probe · run without screen refresh
define find matches
delete all of [seen v]
delete all of [qx v]
delete all of [qy v]
delete all of [matchKeys v]
set [k0 v] to (join (round (newX)) (join [,] (round ((newY) * (2)))))
add (k0) to [seen v]
add (k0) to [matchKeys v]
add (newX) to [qx v]
add (newY) to [qy v]
repeat until <(length of [qx v]) = (0)>
  set [cx v] to (item (1) of [qx v])
  set [cy v] to (item (1) of [qy v])
  delete (1) of [qx v]
  delete (1) of [qy v]
  set [px v] to ((cx) + (26))
  set [py v] to ((cy) + (0))
  visit for match :: custom
  set [px v] to ((cx) + (-26))
  set [py v] to ((cy) + (0))
  visit for match :: custom
  set [px v] to ((cx) + (13))
  set [py v] to ((cy) + (22.5))
  visit for match :: custom
  set [px v] to ((cx) + (-13))
  set [py v] to ((cy) + (22.5))
  visit for match :: custom
  set [px v] to ((cx) + (13))
  set [py v] to ((cy) + (-22.5))
  visit for match :: custom
  set [px v] to ((cx) + (-13))
  set [py v] to ((cy) + (-22.5))
  visit for match :: custom
end

Tick the box. In the Scratch editor, right-click the define block, choose Edit, and tick Run without screen refresh for find matches, visit for match, find anchored and visit for anchor. Without it, every pass of repeat until waits for the next frame and the search takes many frames, like Bubble Chain. The block pictures cannot show the tick, so the panels say so in their labels.

5

Which bubbles still hang from the ceiling?

If the group pops, some bubbles may lose their connection to the ceiling. The same search finds the ones that keep it. This time it starts from all eight slots of the top row, accepts a bubble of any colour, and skips the bubbles that are about to pop. Every key it reaches goes into anchoredKeys; bubbles not in that list will fall.

Probe · run without screen refresh
define find anchored
delete all of [seen v]
delete all of [qx v]
delete all of [qy v]
set [px v] to (-91)
set [py v] to (147)
repeat (8)
  visit for anchor :: custom
  change [px v] by (26)
end
repeat until <(length of [qx v]) = (0)>
  set [cx v] to (item (1) of [qx v])
  set [cy v] to (item (1) of [qy v])
  delete (1) of [qx v]
  delete (1) of [qy v]
  set [px v] to ((cx) + (26))
  set [py v] to ((cy) + (0))
  visit for anchor :: custom
  set [px v] to ((cx) + (-26))
  set [py v] to ((cy) + (0))
  visit for anchor :: custom
  set [px v] to ((cx) + (13))
  set [py v] to ((cy) + (22.5))
  visit for anchor :: custom
  set [px v] to ((cx) + (-13))
  set [py v] to ((cy) + (22.5))
  visit for anchor :: custom
  set [px v] to ((cx) + (13))
  set [py v] to ((cy) + (-22.5))
  visit for anchor :: custom
  set [px v] to ((cx) + (-13))
  set [py v] to ((cy) + (-22.5))
  visit for anchor :: custom
end
Probe · run without screen refresh
define visit for anchor
set [pk v] to (join (round (px)) (join [,] (round ((py) * (2)))))
if <<<<not <([abs v] of (px)) > (92)>> and <not <(py) > (148)>>> and <not <[seen v] contains (pk)?>>> and <not <[matchKeys v] contains (pk)?>>> then
  add (pk) to [seen v]
  go to x: (px) y: (py)
  if <<<<<<touching (Bubble1 v)?> or <touching (Bubble2 v)?>> or <touching (Bubble3 v)?>> or <touching (Bubble4 v)?>> or <touching (Bubble5 v)?>> or <touching (Bubble6 v)?>> then
    add (px) to [qx v]
    add (py) to [qy v]
    add (pk) to [anchoredKeys v]
  end
end

The probe message runs both searches. It only looks for anchored bubbles when something pops, and copies the match into popKeys only when it has three or more bubbles.

Probe
when I receive [probe v]
find matches :: custom
delete all of [anchoredKeys v]
if <(length of [matchKeys v]) > (2)> then
  find anchored :: custom
end
delete all of [popKeys v]
if <(length of [matchKeys v]) > (2)> then
  set [k v] to (1)
  repeat (length of [matchKeys v])
    add (item (k) of [matchKeys v]) to [popKeys v]
    change [k v] by (1)
  end
end
6

Every clone checks its own key

The Probe only produces lists. The clones act on them: each one asks whether popKeys contains its myKey (pop), or whether something popped and anchoredKeys does not contain it (fall). Everyone else stays. The pop and fall animations are normal loops, so they play over the next frames while the search itself is already finished.

Bubble1
when I receive [resolve v]
if <(isClone) = (1)> then
  if <[popKeys v] contains (myKey)?> then
    go to [front v] layer
    repeat (6)
      change size by (8)
      change [ghost v] effect by (16)
    end
    delete this clone
  end
  if <<(length of [popKeys v]) > (0)> and <not <[anchoredKeys v] contains (myKey)?>>> then
    change [dropped v] by (1)
    set [vy2 v] to (1)
    repeat (30)
      change y by (vy2)
      change [vy2 v] by (-0.8)
      if <(y position) < (-150)> then
        change [ghost v] effect by (12)
      end
    end
    delete this clone
  end
end
7

The Shooter ties it together

The Shooter aims at the mouse, flies until it touches any bubble or the ceiling, and snaps to the nearest slot. Then it runs the phases in order, each with broadcast and wait: add bubble, probe, resolve. The variable phase shows where the game is (aim, fly, probe, resolve).

Shooter
when I receive [play v]
set [phase v] to [aim]
set [shotColor v] to (pick random (1) to (4))
set [clicked v] to (0)
go to x: (0) y: (-150)
show
go to [front v] layer
forever
  switch costume to (shotColor)
  go to x: (0) y: (-150)
  set [aimDY v] to ((mouse y) - (-150))
  if <(aimDY) < (8)> then
    set [aimDY v] to (8)
  end
  set [aimDir v] to ([atan v] of ((mouse x) / (aimDY)))
  if <(aimDir) > (78)> then
    set [aimDir v] to (78)
  end
  if <(aimDir) < (-78)> then
    set [aimDir v] to (-78)
  end
  if <<<key (space v) pressed?> or <key (up arrow v) pressed?>> or <(clicked) = (1)>> then
    set [clicked v] to (0)
    set [phase v] to [fly]
    set [vx v] to (([sin v] of (aimDir)) * (4))
    set [vy v] to (([cos v] of (aimDir)) * (4))
    repeat until <<<<<<<touching (Bubble1 v)?> or <touching (Bubble2 v)?>> or <touching (Bubble3 v)?>> or <touching (Bubble4 v)?>> or <touching (Bubble5 v)?>> or <touching (Bubble6 v)?>> or <(y position) > (147)>>
      repeat (3)
        if <not <<<<<<<touching (Bubble1 v)?> or <touching (Bubble2 v)?>> or <touching (Bubble3 v)?>> or <touching (Bubble4 v)?>> or <touching (Bubble5 v)?>> or <touching (Bubble6 v)?>> or <(y position) > (147)>>> then
          change x by (vx)
          change y by (vy)
          if <(x position) > (91)> then
            set x to (91)
            set [vx v] to ((vx) * (-1))
          end
          if <(x position) < (-91)> then
            set x to (-91)
            set [vx v] to ((vx) * (-1))
          end
        end
      end
    end
    set [row v] to (round (((147) - (y position)) / (22.5)))
    if <(row) < (0)> then
      set [row v] to (0)
    end
    set [col v] to (round ((((x position) - (-91)) - (((row) mod (2)) * (13))) / (26)))
    if <(col) < (0)> then
      set [col v] to (0)
    end
    if <(col) > ((7) - ((row) mod (2)))> then
      set [col v] to ((7) - ((row) mod (2)))
    end
    set [newX v] to (((-91) + ((col) * (26))) + (((row) mod (2)) * (13)))
    set [newY v] to ((147) - ((row) * (22.5)))
    set [newColor v] to (shotColor)
    hide
    broadcast (add bubble v) and wait
    set [phase v] to [probe]
    set [dropped v] to (0)
    broadcast (probe v) and wait
    set [markedCount v] to (length of [matchKeys v])
    set [phase v] to [resolve]
    broadcast (resolve v) and wait
    set [shotColor v] to (pick random (1) to (4))
    set [phase v] to [aim]
    show
  end
end

How well does it work?

Automated tests fire 25 shots at random boards and compare the result with an exact flood fill on a grid. Every shot matched. The search always finished within the frame the shot landed in, and the slowest of those frames took about 4 ms of real time; a Scratch frame lasts 33 ms.

Bubble ChainBubble Probe
How the chain is foundGlowing rings spread from bubble to bubble with touching colorAn invisible Probe visits neighbour slots with touching sprite
TimeOne frame per ring of bubblesOne frame
Extra artRing costumes in special detector coloursNone
SpritesOne Bubble sprite with colour costumesOne sprite per colour
Best forSeeing the chain spreadInstant, exact results

Things that went wrong on the way

  • Hidden sprites touch nothing. Use the ghost effect at 100 to make the Probe invisible.
  • Shared counters in normal loops get mixed up. Scripts that run at the same time take turns after every loop pass. Put such loops in a custom block that runs without screen refresh, or give each sprite its own variables.
  • Probe from the slot centre, not the shot's position. The shot stops wherever it first touches a bubble; snap it to a slot before searching, or the neighbour offsets miss.
  • Keep the result in its own phase. Separating probe from resolve made it possible to measure the search on its own, without the pop animation.
