Bubble Probe: finding a colour chain in one frame

In a bubble shooter, the bubble you fire joins a group of the same colour. If the group has three or more, it pops, and anything left hanging falls. This tutorial shows how to find that group in Scratch, using touching blocks instead of a grid list, and how to make the whole search happen between two screen refreshes.

The idea

The earlier Bubble Chain demo let the chain spread visibly: each round, bubbles touching a glowing ring put on a ring of their own. It works, but it takes one frame per ring of bubbles. Bubble Probe gets the same answer at once by combining three things:

One sprite per colourBubble1 … Bubble6. Asking touching Bubble3? means "is a blue bubble here?".
An invisible ProbeA tiny dot that jumps to a slot and asks that question. It never shows on screen.
Run without screen refreshThe Probe's custom blocks finish all their loops before Scratch draws the next frame.
1

A honeycomb board made of clones

The board has 12 rows of 8 slots. Odd rows are shifted half a bubble to the right and hold 7 bubbles. Bubbles are 26 pixels wide and rows are 22.5 pixels apart, so a slot's centre is:

  • x = -91 + col × 26 + (row mod 2) × 13
  • y = 147 − row × 22.5

The starting board is the list layout: 96 items, one per slot, holding a colour number or 0 for empty. When the list is empty the Stage fills it with a random board first.

Why a custom block? All six sprites receive fill board together and share the counter i. A normal repeat loop pauses after every pass to let the other scripts run, so the six loops kept changing each other's i and no clones were made. A custom block that runs without screen refresh finishes its whole loop before any other script gets a turn.

2

A name for every slot

The search needs to remember which slots it has already visited, and each clone needs to know whether it was chosen. Both use a key: the slot's x and twice its y, rounded and joined with a comma, for example -13,294. Twice y keeps the half pixels of the 22.5 row height, so every slot gets its own key. Each clone works out its key once, when it starts, in its local variable myKey.

3

The Probe: look at the six neighbours

The Probe is a 4 × 4 pixel dot. It is shown, but with the ghost effect at 100, so it is invisible yet still counts for touching. A hidden sprite never touches anything.

Probe

The visit is one custom block. It skips slots outside the walls and above the ceiling, and slots already in seen. Otherwise it records the slot as seen, moves there and asks touching (join "Bubble" newColor)?. If the answer is yes, the slot joins the match and goes into the queue so its own neighbours are checked later.

4

Walk the whole chain with a queue

A queue is a to-do list of slots whose neighbours still need checking. Scratch has no list of pairs, so the queue is two lists side by side: qx and qy. The search:

  1. Starts with the bubble that just landed: its key goes into seen and matchKeys, its position into the queue.
  2. Takes the first slot out of the queue.
  3. Visits its six neighbours. Matching ones join the queue.
  4. Repeats until the queue is empty.

Programmers call this a breadth-first search, or a flood fill. At the end, matchKeys lists every bubble in the group.

Probe · run without screen refresh

Tick the box. In the Scratch editor, right-click the define block, choose Edit, and tick Run without screen refresh for find matches, visit for match, find anchored and visit for anchor. Without it, every pass of repeat until waits for the next frame and the search takes many frames, like Bubble Chain. The block pictures cannot show the tick, so the panels say so in their labels.

5

Which bubbles still hang from the ceiling?

If the group pops, some bubbles may lose their connection to the ceiling. The same search finds the ones that keep it. This time it starts from all eight slots of the top row, accepts a bubble of any colour, and skips the bubbles that are about to pop. Every key it reaches goes into anchoredKeys; bubbles not in that list will fall.

6

Every clone checks its own key

The Probe only produces lists. The clones act on them: each one asks whether popKeys contains its myKey (pop), or whether something popped and anchoredKeys does not contain it (fall). Everyone else stays. The pop and fall animations are normal loops, so they play over the next frames while the search itself is already finished.

The Shooter ties it together

The Shooter aims at the mouse, flies until it touches any bubble or the ceiling, and snaps to the nearest slot. Then it runs the phases in order, each with broadcast and wait: add bubble, probe, resolve. The variable phase shows where the game is (aim, fly, probe, resolve).

8

The same search with recursion

A custom block may call itself, and its inputs belong to each call separately. That makes the queue unnecessary: match at (x) (y) checks one slot and, if it holds a bubble of the right colour, calls itself for the six neighbours. Each call keeps its own x and y; only seen and matchKeys are shared.

Probe · run without screen refresh

The anchor search changes the same way, and one more block starts both searches. The variable method chooses the version: queue, slow, or anything else for recursion, the default.

Probe · run without screen refresh

Screen refresh matters even more here. Without the tick, Scratch pauses until the next frame every time a block calls itself. The slow version, identical apart from the tick, needed up to 63 frames for one search. The starter block also needs the tick: in a plain script its repeat 8 over the top row paused after each pass, and a search took 7 frames.

Both versions give exactly the same results. The recursive one is shorter and easier to read; the queue version shows the order of the search more plainly and never grows deep.

How well does it work?

Automated tests fire 25 shots at random boards and compare the result with an exact flood fill on a grid. Every shot matched. The search always finished within the frame the shot landed in, and the slowest of those frames took about 4 ms of real time; a Scratch frame lasts 33 ms.

Things that went wrong on the way

  • Hidden sprites touch nothing. Use the ghost effect at 100 to make the Probe invisible.
  • Shared counters in normal loops get mixed up. Scripts that run at the same time take turns after every loop pass. Put such loops in a custom block that runs without screen refresh, or give each sprite its own variables.
  • Probe from the slot centre, not the shot's position. The shot stops wherever it first touches a bubble; snap it to a slot before searching, or the neighbour offsets miss.
  • Keep the result in its own phase. Separating probe from resolve made it possible to measure the search on its own, without the pop animation.
